# GTN1 Windows desktop → GTN2 Flutter source map

**Authority:** `ne0gl1tch20/GuessTheNumber` at `fe9cf567169e19059e0330d08769fe454336ef94`  
**GTN2 snapshot inspected:** `main` at `7e05ca4e472836455f15b145cadab71fcbc6d831`  
**Inventory:** `docs/GTN1_SOURCE_INVENTORY.json` — 55 desktop production Kotlin files and 29 desktop Kotlin tests.

This is a file-level migration map, not a parity-completion claim. GTN1's Windows host uses Compose Desktop and WebView. GTN2 uses native Dart/Flutter UI and generates the Windows runner in CI with `flutter create --platforms=windows`; the generated runner is not committed to this repository. WebView/Compose plumbing is therefore not copied literally, but the user-facing behavior and Windows-specific services still require equivalents.

## Status definitions

- **Mapped:** a corresponding Dart/platform implementation and relevant test surface are present; source-case parity remains governed by the main checklist.
- **Partial:** a destination exists, but the source contract is broader, a platform behavior is unverified, or coverage is incomplete.
- **Gap:** no equivalent behavior or regression surface was found in the inspected GTN2 snapshot.
- **N/A:** the source implementation is specific to Compose/WebView and is intentionally replaced by native Flutter. This does not waive any user-facing behavior it owned.

## 3. Windows host and build facts

- GTN2 does **not** currently commit a generated `windows/runner` host. Both `.github/workflows/build.yml` and `.github/workflows/validate.yml` explicitly run `flutter create --platforms=windows --project-name=gtn_2 --org=com.jarrlyyy .` before building. The Windows target is therefore generated in CI rather than maintained as checked-in native runner code.
- The tracked Windows-specific source currently includes `windows/installer/gtn2.iss`. It packages the generated Release runner output; installer behavior still requires real Windows verification.
- `lib/data/updates/update_checker.dart` contains a Windows release manifest reader, bounded archive download, SHA-256 verification and PowerShell replacement/restart flow. This is a real mapped implementation, not a missing updater; archive structure validation, rollback and runtime recovery remain open.
- GTN1 WebView/Edge controllers and message envelopes are technology-specific. Their transport is N/A after moving to native Flutter, but their actual user-facing actions must be mapped to validated Dart callbacks.
