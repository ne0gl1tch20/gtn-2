# GTN2 Android debug signing

GTN2 uses one persistent Android signing identity for every distributable debug APK. Do not use the temporary Android/Flutter debug keystore generated by CI. Replacing the signing key later prevents Android from installing an update over an existing installation.

## Create the permanent key (Windows)

Run PowerShell from a private folder outside the repository:

\`\`\`powershell
powershell -ExecutionPolicy Bypass -File .\scripts\create_android_signing_key.ps1 -OutputDirectory "$HOME\GTN2-signing-backup"
\`\`\`

The script creates:

- \`gtn2-debug-signing.jks\`: the private keystore backup.
- \`GTN2_DEBUG_KEYSTORE_BASE64.txt\`: the base64 value for the GitHub secret.
- Alias: \`gtn2-debug\`.

Choose two strong, unique passwords and store them in a password manager. Keep the JKS and base64 file in an encrypted/offline backup. Never upload either file to the repository or share them in chat.

## Add GitHub Actions secrets

Open **ne0gl1tch20/gtn-2 → Settings → Secrets and variables → Actions → New repository secret** and create all four:

| Secret | Value |
|---|---|
| \`GTN2_DEBUG_KEYSTORE_BASE64\` | Entire contents of \`GTN2_DEBUG_KEYSTORE_BASE64.txt\` |
| \`GTN2_DEBUG_KEY_ALIAS\` | \`gtn2-debug\` |
| \`GTN2_DEBUG_KEY_PASSWORD\` | Private key password entered during generation |
| \`GTN2_DEBUG_STORE_PASSWORD\` | Keystore password entered during generation |

Do not put the password or base64 value in workflow YAML, Dart code, issue comments, or commits.

## CI signing behavior

The main/master build job:

1. Builds the Flutter debug APK.
2. Aligns it with Android SDK \`zipalign\`.
3. Signs it with the permanent PKCS#12 keystore using \`apksigner\`.
4. Runs \`apksigner verify --verbose --print-certs\` and extracts the certificate SHA-256 fingerprint.
5. Uploads the signed APK and public certificate fingerprint as seven-day artifacts.

The pull-request validation workflow remains unsigned because it only compiles/tests and does not distribute an installable update. Release publishing remains behind the existing parity gate.

## Key rotation

Do not regenerate the key after the first signed release. Keep at least two secure backups. Losing the keystore means existing signed installs cannot receive in-place updates from a newly signed APK.
